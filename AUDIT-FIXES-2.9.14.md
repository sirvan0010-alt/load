# Audit fixes 2.9.14

## 1. SmartPace / per-recipient ordering

A worker no longer consumes a global pacing slot before waiting for a full
per-recipient window. The recipient reservation is acquired first, then the
global spacing slot. If cancellation occurs during global pacing, the
recipient reservation is released.

This prevents a worker from waiting on a recipient window after its global
slot has already elapsed and then sending without a fresh global spacing
interval.

Regression test:
`PerRecipientLimit_DoesNotConsumeGlobalSlotWhileBlocked`.

## 2. MX response hardening

The raw MX parser now:
- requires exactly one question (the query generated by MailLoadTester),
- rejects non-standard DNS opcodes,
- rejects truncated UDP responses instead of parsing partial answers,
- validates compression-pointer targets,
- rejects malformed/truncated answer records,
- ensures the MX exchange name stays within the RR's RDATA boundary.

This is deliberately fail-closed: malformed DNS responses are not converted
into plausible MX results.

## 3. Version consistency

Application version is 2.9.14 and the GUI title + Inno Setup template use
`AppVersion.Current` / 2.9.14 rather than stale hard-coded versions.

## Test execution

The source includes regression tests, but this environment has no .NET 8 SDK,
so `dotnet test` and the Windows Release build were not executed here.

## 5. SMTP pool connect-vs-dispose race

`RentAsync` now re-checks the disposed flag after Connect/Auth completes. If
shutdown began while the network operation was in flight, the newly connected
client is disposed and is not handed to the caller.
